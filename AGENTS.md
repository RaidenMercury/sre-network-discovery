# SRE Network Discovery Project Rules

1. **Automatic Orchestration**:
   - For any development, architectural planning, bug fixing, or feature addition in this repository, always activate and adhere to the project skill: `sre-orchestrator`.

2. **Integration of Core Toolchains**:
   - **Graphify**: Maintain the codebase knowledge graph (`graphify .` / `graphify --update`) and query relationships before refactoring or adding modules.
   - **Superpowers Pipeline**: Follow the disciplined cycle: `brainstorming` -> `writing-plans` -> `test-driven-development` -> `systematic-debugging` -> `verification-before-completion`.
   - **Ponytail / Minimal Code**: Reject bloat, enforce YAGNI, prefer native platform APIs and standard libraries, and run `ponytail-review` before finalizing changes.

3. **Domain & Interface Standards**:
   - Leverage installed specialized plugins:
     - `web-ts-js`: For TypeScript/JavaScript modules and modern web interface components.
     - `native-systems`: For high-throughput C++ / C# (.NET) network discovery engines and native app UI architecture.
     - `modern-web-guidance-plugin` & `chrome-devtools-plugin`: For web standards, accessibility, and DevTools troubleshooting.
     - `flutter` & `android-cli-plugin`: For mobile/cross-platform client interfaces.
